# R6 integration preparation — product activation remains blocked

[R6 #10](https://github.com/LounaMaili/LMThermal/issues/10) depends on both R4 and
[R5 Desktop #2](https://github.com/LounaMaili/LMThermal-Desktop/issues/2), plus selected
backend assurance. The present campaign authorizes architecture only. Nothing here
activates a product recorder, changes the frozen wire or reopens accepted owner choices.

## Retain accepted choices

Analysis remains the default with a visible explicit first-module preservation choice,
remembered visible per-module selection and Native/Full choices where capabilities
support them. No initial low-level payload checkbox UI. Unknown supported-backend
capacity warns and permits Start; known insufficient startup+reserve refuses. Storage
estimates count physical roles after restricted same-frame view dedup, masks, metadata,
worst-case codec expansion and reserve. Never promise a compression ratio or silently
downgrade evidence/cadence to make admission pass.

## Intended integration seams

- Subscribe once to authoritative module observations BEFORE presentation conflation;
  keep the existing single camera owner, explicit radiometric initialization and source
  intake witnesses. Recorder lifetime is separate from Compose render cadence.
- Present pending, footer-synchronized committed measurements and separately counted
  preparation/writer/source gaps. Only acknowledged observations may be called saved.
  First failure and terminal reason are distinct diagnostics, not hidden by a green UI.
- Start uses conservative negotiated maxima and simultaneous-lifetime ownership bounds;
  live Java heap, cumulative allocations, native memory, RSS/PSS and logical reservation
  are separate facts. Keep78+32MiB and existing queue bounds until a reviewed new model.
- Retained rotation/approved picker continuity keeps one owner. Ordinary background,
  screen-off/locale/detach/fatal/Close must follow approved awaited Stop/seal/release
  policy. Do not add a service, forced GC or another process to evade memory admission.
- Canonical app-owned local storage is independent of immutable prepared still exports.
  Finalized access must not require a second full copy. Sharing/export cannot certify
  destination durability merely from close or source END; verify independent destination
  bytes, keep source unchanged and disclose provider/lifetime/privacy limits.
- Desktop uses stored Float32/masks/native/transport, indexed intake chronology and
  explicit gaps. No thermometry recomputation, parent rewriting or legacy relabeling.

## Required gates before activation

1. Explain or reproduce the historical unrepresented-loss fatal sufficiently to assess
   safety under plausible control-reserve/process-order races; never allow END after it.
2. Establish appropriate sustained R4 cadence/freshness and memory admission with normal
   Compose preview on authorized physical hardware. Finite emulator catch-up is not a
   physical acquisition rate. Refuse unsafe Start; no arbitrary budget reduction.
3. Produce real Android LMTR outputs and verify independent Float32/native/transport,
   clocks, gaps and source immutability through Desktop Linux and native Windows. The
   current155-measurement synthetic ART→R5 check is useful but does not satisfy this gate.
4. Validate actual backend write/sync/close/export/refusal/recovery boundaries. No generic
   SAF/remote durability or physical power-loss certification follows from current tests.
5. Review integrated product lifecycle/admission/status design; then authorize R6 code.

A future physical session additionally requires explicit owner authorization, Pixel
released from LMarchery, wireless ADB/permissions legitimately available, approved
non-sensitive scene, camera attached normally and battery/thermal/storage/memory checks.
No physical action or ADB discovery is part of this campaign.

Native-equivalent temperatures; absolute physical accuracy not yet independently validated.
