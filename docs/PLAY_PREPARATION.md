# Google Play technical preparation

Review date: 2026-11-12. Development branch only; no Console/account interaction,
key generation, signing, submission or public release is authorized by this preparation.
Current API requirements must be rechecked before any submission.

## Official requirements and implemented preparation

Google's [target API policy](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
requires API 36 for new mobile apps/updates since 2026-08-31; the published extension
ended 2026-11-01. This isolated branch moves compile/target SDK 35 to **36** and pins
build tools 36.0.0. AGP 8.9.2 meets the
[Android 16 SDK setup minimum](https://developer.android.com/about/versions/16/setup-sdk).
A technical adaptive launcher icon and pre-31 backup exclusions are included; the icon
is a reviewable placeholder, not accepted store branding. Min SDK remains 26; the only packaged ABI remains arm64-v8a. Do not imply support for
32-bit-only or x86 devices. Hardware USB host is required; an internal phone camera is
optional. The app can start without a compatible camera and show an unavailable state.

The [Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16)
require runtime review: edge-to-edge/insets, predictive Back, large-screen adaptive
layout, locale/font scaling, configuration lifetime and SAF return/cancellation. The
workspace already reserves safe drawing insets and uses native geometry; no orientation
lock or old onBackPressed override is introduced. Host tests are not Android 16 runtime
qualification. No ART/device or hosted CI is run in this phase.

Build an [Android App Bundle](https://developer.android.com/guide/app-bundle) with
`:app:bundleRelease`; `:app:assembleRelease` produces an unsigned APK for technical
inspection. Release is intentionally unsigned unless the owner later provides the
external properties file described in [configuration](CONFIGURATION.md).
[Play App Signing/upload keys](https://developer.android.com/studio/publish/app-signing)
are distinct responsibilities: choose custody, backup and rotation before provisioning
keys. No debug-key fallback or key is generated by this work. Never commit secrets or
put password arguments in a published build transcript. Store identity/version code,
branding, final application ID and signing ownership still require product approval.

## Native packaging

The [16 KiB page-size requirement](https://developer.android.com/guide/practices/page-sizes)
applies to applicable Play submissions. AGP >=8.5.1 and NDK r28 are the documented baseline;
this project uses 8.9.2 / 28.0.13004108. Inspect every built .so, including dependencies:

```sh
python3 tools/inspect_android_release.py app/build/outputs/apk/release/app-release-unsigned.apk
python3 tools/inspect_android_release.py app/build/outputs/bundle/release/app-release.aab
"$ANDROID_HOME/build-tools/36.0.0/zipalign" -c -P 16 -v 4 app/build/outputs/apk/release/app-release-unsigned.apk
# With an independently provisioned official bundletool:
java -jar bundletool-all.jar dump config --bundle=app/build/outputs/bundle/release/app-release.aab
```

The AAB should request `PAGE_ALIGNMENT_16K`; verify generated split APKs as well. Static
ELF/ZIP checks do not establish successful execution on a 16 KiB Android runtime. JNI
sources and USB code are unchanged. libusb, libuvc and the JNI bridge are separate shared
objects; no proprietary thermometry APK binary is shipped. The Kotlin thermometry remains
the validated native-equivalent implementation. Required licence/source/relink obligations
must be reviewed for the actual signed delivery, including NDK C++ runtime and AndroidX.

## Permissions, data and privacy audit

| Area | Current source/configuration | Remaining release review |
| --- | --- | --- |
| USB | Required USB Host; installed module match and Android per-device authorization | Device compatibility list and permission-denial recovery |
| Camera | CAMERA runtime permission before native USB acquisition | Explain external thermal camera use; no background recording claim |
| Files | SAF CreateDocument; private staged captures; nonexported FileProvider and temporary read grants | Local/cloud provider behavior and user expectations |
| Networking/accounts | No INTERNET permission, app account, analytics or crash-upload SDK in current source | Re-audit final merged manifest and dependencies |
| Backup | allowBackup=false; data extraction exclusions | Device-transfer/OS behavior review |
| Diagnostics | NumericEvidence disabled before serialization in release; OS technical/error logs remain | Frame/session counters and exporter technical logs still exist; audit paths/derived metadata before shipping |
| Measurements | Local thermal images, settings, native-equivalent Float32, ROI and provenance | Potentially sensitive scenes; user-controlled export/Share |

Do not request broad storage, MANAGE_EXTERNAL_STORAGE, location, background CAMERA,
or foreground services just for export. SAF providers and selected Share recipients may
upload files independently; absence of INTERNET in this app does not guarantee files
stay on the phone after explicit export. Debug builds are not store artifacts.

The [Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)
requires a developer declaration covering actual app and SDK behavior; do not preselect
"no data collected" as an automatic consequence of local processing. Review user-initiated
sharing exceptions, all dependencies and final release logs. The
[User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)
requires a truthful privacy policy. [Draft policy content](PRIVACY_POLICY_DRAFT.md) is a
review aid, not an approved/public URL. Before submission provide owner identity/contact,
public policy URL and in-app access, retention/deletion details and consistent store text.
No Google account, Console form or final policy is created here.

## Remaining product and qualification gates

- Select top-level application license; both repositories currently lack one. Review
  vendored `third_party` notices, assets/licenses, upstream modified sources and LGPL
  replace/relink/source availability. Do not treat a notice list as legal certification.
- Final app icon, store screenshots/description, version scheme, support contact, device
  requirements, age/content/data declarations and actual test-track requirements need owner review.
- Complete API 26/32/35/36, 16 KiB, small/large screen, TalkBack and native module regressions
  in a separately authorized environment. No new Pixel/HT-301 validation is claimed.
- Test denied CAMERA/USB, unsupported/absent camera, explicit initialization, stale values,
  SAF cancellation, Back/Home/screen-off/rotation/locale and source integrity in signed builds.
- R4/R6 recording remains absent. No store wording may promise common LMTR recording or
  independent physical calibration. Independent performance/temperature claims need evidence.

**Native-equivalent temperatures; absolute physical accuracy not yet independently validated.**

## Host qualification receipt

The API 36 branch passes 234 core JVM and 27 app local/Robolectric tests, debug and
instrumentation APK compilation, unsigned release APK/AAB compilation and release lint
(zero errors). Ten localization checker self-tests and 120 en/fr keys pass, camera module
boundaries pass, and two ELF refusal tests pass. No ART/physical test is included.

The final unsigned AAB is 7,900,760 bytes, SHA-256
`e7f577209e10d653384ba25aa4a71dc605cb108f82887c0cf6a4b1d4d3dc1ae8`.
The unsigned APK is 8,092,146 bytes, SHA-256
`f823beebcbca5f74220c24c9f355d5f7acabec7f41bcbe1392c53b8aea07547f`.
All four packaged arm64 libraries have ELF LOAD alignment 16,384 bytes; APK stored
libraries also pass the 16 KiB ZIP check and Android zipalign. The AAB's BundleConfig
was parsed with the cached official bundletool 1.17.2 Config/protobuf classes:
uncompress native libraries enabled, `PAGE_ALIGNMENT_16K`. This is a configuration
inspection, not generated-split/device validation. Jarsigner reports the AAB unsigned.
Artifacts and exact probe source/logs stay private, outside Git.

Remaining lint warnings are recorded rather than suppressed: newer instrumentation
runner available, no ChromeOS x86_64 ABI, redundant v26 launcher-resource qualifier on this minSdk,
two now-unused diagnostics strings and an optional monochrome launcher icon. The colored
adaptive icon is a technical placeholder. These do not constitute Play acceptance; the
runtime/branding/signing/privacy/licensing gates above remain open.
